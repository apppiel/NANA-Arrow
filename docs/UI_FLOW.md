## 1. 전체 흐름
```
[Boot] 로딩 ─▶ [Main] ─ 시작하기 ───────────▶ [Game Lv N]
                 │  └ 레벨 선택 ─ 레벨 탭 ─▶ [Game Lv K]
                 │  └ 설정 팝업
                 │  └ 응모 코드 보기 (100 클리어 후)
                 └ 뒤로가기 ─▶ 종료 확인

[Game] 탭 플레이
  ├ 모든 화살표 Exit ─(clearPopupDelay)─▶ 클리어 팝업
  │     ├ 다음 레벨 ─▶ (전면 광고 판정) ─▶ [Game Lv N+1]
  │     │               └ Lv100 클리어였다면 응모 코드 팝업 먼저
  │     └ 메인으로 ─▶ (전면 광고 판정) ─▶ [Main]
  ├ 하트 0 ─▶ 실패 팝업
  │     ├ 광고 보고 이어하기 ─▶ 보상형 광고 ─ 보상 ─▶ 하트 +1, 같은 보드에서 계속
  │     └ 다시하기 ─▶ (전면 광고 판정) ─▶ 같은 레벨 처음부터
  └ 설정 버튼 ─▶ 설정 팝업 (다시하기 / 메인으로 / 사운드)
```
- 광고 판정은 전부 `AdsManager` 가 한다. UI 는 이벤트만 보내고 광고가 끝났다는 콜백을 받은 뒤 다음 화면으로 간다 (§8 표)

## 2. 공통 규칙
- 세로 고정, Safe Area 안에 HUD·버튼 배치
- 팝업이 열려 있는 동안 보드 입력 차단. 팝업은 한 번에 하나 (응모 코드 → 클리어 순서처럼 연속일 때는 앞 팝업을 닫고 다음을 연다)
- 버튼: 주 버튼 1개(크고 채운 색) + 보조 버튼(외곽선 또는 텍스트). 최소 터치 영역 약 48dp
- 문구는 키로 관리 (§9 표). v1 은 한국어만 ⚠
- 팝업 열림·닫힘 시간, 로딩 최소 시간 등 UI 수치는 전부 인스펙터 값 (예: `UIConfig` ScriptableObject)
- **Android 뒤로가기**
| 위치 | 동작 |
|---|---|
| 팝업 열림 | 팝업 닫기와 같음. 단 실패 팝업·응모 코드 팝업은 닫히지 않음(선택 강제) |
| Game (팝업 없음) | 설정 팝업 열기 |
| 레벨 선택 | Main 으로 |
| Main | 종료 확인 팝업 |

## 3. Boot
- 화면: 배경 + 로고(NANABOX) + 로딩 표시
- 하는 일: 저장 데이터 로드 → 설정(사운드) 적용 → 광고 SDK 초기화 시작(**완료를 기다리지 않음**, 실패해도 진행) → Main
- 최소 표시 시간 `bootMinDuration` (기본 1.0초) — 로고가 깜빡이고 사라지지 않도록

## 4. Main
| 요소 | 내용 |
|---|---|
| 타이틀 | 게임 로고 |
| 주 버튼 | **시작하기** + 아래 작은 글씨 `레벨 N` (N = 아직 안 깬 가장 낮은 레벨. 전부 깼으면 마지막 레벨) |
| 보조 버튼 | **레벨 선택** |
| 우상단 | 설정(톱니) 아이콘 → 설정 팝업(Main 버전) |
| 조건부 | 100 클리어 후 **응모 코드 보기** 버튼 표시 |

### 레벨 선택 (Main 안의 패널)
- 5열 그리드, 세로 스크롤. 상단 좌측 뒤로(←), 가운데 `레벨 선택`
- 칸 상태 3가지: **클리어**(체크 표시) / **다음 도전**(강조 테두리) / **잠김**(자물쇠, 탭하면 흔들림만)
- 열리는 조건: 클리어한 레벨 + 그 다음 1개. 클리어한 레벨은 다시 플레이 가능
- 별점 없음 (GAME_RULES §5)

## 5. Game
```
┌───────────────────────────────┐
│ [⚙]        레벨 12     ♥ ♥ ♥ │  ← HUD (상단, Safe Area)
│                               │
│   (튜토리얼 문구 영역, 평소 비움) │
│                               │
│          ┌─────────┐          │
│          │  보 드   │          │  ← 화면 중앙, 자동 스케일
│          └─────────┘          │
│                               │
│   (아래쪽 비움: 부스터·코인 없음)  │
└───────────────────────────────┘
```
- **HUD**: 좌측 설정 버튼, 가운데 `레벨 N`, 우측 하트 3개 (GAME_RULES §9)
- **하트 감소**: 해당 하트가 흔들리며 빈 하트로 바뀜 + 진동(⚠ 진동 옵션). 이어하기로 회복하면 빈 하트가 다시 채워지는 연출
- **Marked(빨간색)**: 화살표 색만 바뀜. 별도 문구 없음 (Lv1 튜토리얼에서만 설명)
- **클리어 순간**: 마지막 Exit 후 입력 즉시 차단 → `clearPopupDelay` 뒤 클리어 팝업
- **앱이 백그라운드로 갔다 돌아옴**: 보드 그대로 유지. 앱이 종료되면 레벨 중간 상태는 저장하지 않고 다음 실행 시 그 레벨 처음부터 ⚠

## 6. 팝업
### 6-1. 클리어
| 요소 | 문구 |
|---|---|
| 제목 | `클리어!` |
| 부제 | `레벨 N` |
| 주 버튼 | `다음 레벨` |
| 보조 버튼 | `메인으로` |
- 두 버튼 모두 누르면 먼저 `LevelCleared` 판정 결과에 따라 전면 광고 → 끝나면 이동 (§8)
- 마지막 레벨(현재 탑재 수) 클리어 시 주 버튼은 `메인으로`, 부제에 `준비된 레벨을 모두 깼어요!`

### 6-2. 실패 (하트 0)
| 요소 | 문구 |
|---|---|
| 제목 | `하트를 모두 잃었어요` |
| 주 버튼 | `광고 보고 이어하기` + 아이콘(▶ + ♥1) |
| 보조 버튼 | `다시하기` |
| 광고 준비 안 됨 | 주 버튼 비활성 + 아래 작은 글씨 `지금은 광고를 불러올 수 없어요` |
- 이어하기를 레벨당 `maxContinues`(1)회 다 쓴 뒤 다시 하트 0 → 주 버튼 숨김, `다시하기` 만 남김 (제목 동일)
- 광고를 끝까지 보지 않고 닫음 → 보상 없음, 실패 팝업 그대로
- 광고 보상 → 팝업 닫고 하트 +`continueLives`, 보드·Marked 상태 그대로 이어서
- 닫기(X) 없음, 뒤로가기로 닫히지 않음 (메인으로 가려면 다시하기 후 설정 이용)

### 6-3. 설정
| 요소 | Main | Game |
|---|---|---|
| 제목 `설정` | O | O |
| `사운드` 켜기/끄기 토글 (BGM·효과음 한 번에) | O | O |
| `진동` 켜기/끄기 토글 ⚠ | O | O |
| `다시하기` | - | O → 확인 없이 바로 레벨 재시작 |
| `메인으로` | - | O → 확인 팝업(6-4) |
| 닫기(X) | O | O |
- Game 에서 설정을 여는 동안 보드 입력 정지 (진행 중 Fire 연출은 끝까지 재생)
- 설정의 `다시하기` 는 **실패로 세지 않음** → `interstitialAfterFails` 카운트 제외, 전면 광고 없음 ⚠

### 6-4. 메인으로 확인 (Game)
- 본문 `메인으로 갈까요?` / 작은 글씨 `진행 중인 레벨은 처음부터 다시 시작해요`
- 주 버튼 `계속하기`(팝업 닫기) / 보조 버튼 `나가기`(Main 으로, 광고 없음)

### 6-5. 응모 코드 (100 클리어)
- 100 클리어 직후 클리어 팝업보다 **먼저** 표시. Main 의 `응모 코드 보기` 로 다시 열 수 있음
- 문구 초안: 제목 `100단계 달성!` / 본문 `아래 코드로 경품 이벤트에 응모할 수 있어요` / 코드 표시 + `코드 복사` / `응모하러 가기`(홈페이지 열기) / `닫기`
- 코드 형식·홈페이지 주소·화면 구성은 **기존 두 게임과 동일하게** — 프로그래머 W-009 조사 결과로 확정

### 6-6. 종료 확인 (Main)
- 본문 `게임을 종료할까요?` / 주 버튼 `취소` / 보조 버튼 `종료`

## 7. 튜토리얼
- 레벨 JSON 이 아니라 `TutorialConfig` ScriptableObject 에 레벨별 항목으로 둔다 (레벨 번호, 문구 키, 손가락이 가리킬 화살표 id, 표시 조건) — 인스펙터에서 수정 가능
- 튜토리얼 중에도 입력은 막지 않는다 (틀려도 목숨 규칙으로 흡수)

## 8. 광고 연결 지점 (GAME_RULES §7)
| UI 동작 | UI 가 보내는 이벤트 | AdsManager 판단 | 끝난 뒤 |
|---|---|---|---|
| 클리어 팝업 버튼 | `LevelCleared(N)` | N > adFreeLevels 이고 클리어 N레벨마다 → 전면 | 다음 레벨 / Main |
| 실패 팝업 `다시하기` | `RetryPressed(N)` (실패 후) | 같은 레벨 실패 `interstitialAfterFails` 회마다 → 전면 | 레벨 재시작 |
| 실패 팝업 `광고 보고 이어하기` | `ContinueRequested(N)` | 레벨당 maxContinues 남았는지 + 보상형 준비 여부 | 보상 → 하트 회복 |
| 설정 `다시하기`, `메인으로` | 없음 | - | 바로 이동 |
- 전면 광고가 준비 안 됐으면 기다리지 않고 바로 이동
- ⚠ 레벨 선택으로 **이미 깬 레벨**을 다시 클리어한 것도 N레벨 카운트에 넣을지 (제안: 넣음 — 클리어 횟수 기준)

## 11. 디렉터 확인 필요 (⚠)
1. **진동 토글** 추가 여부 (GAME_RULES 는 사운드 토글만 명시). 제안: 추가, 기본 켜짐, 하트 감소 시에만 진동
2. **설정의 다시하기**는 실패로 세지 않고 광고도 없음 — 제안대로 확정할지
3. **레벨 중간 저장 없음** (앱 종료 시 그 레벨 처음부터) — 확정할지
4. **v1 언어 한국어만** — 확정할지 (스토어 출시 국가와 연결)
5. **재플레이 클리어도 전면 광고 카운트 포함** — 확정할지
