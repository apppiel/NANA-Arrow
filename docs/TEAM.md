# NANA-Arrow — TEAM.md (팀 구성과 직책)

| 직책 | 담당 | 어디서 | 한 줄 역할 |
|---|---|---|---|
| **팀장** | 사용자 (최승진) | Unity 에디터, 최종 결정 | 결정권자. 에디터에서 씬·프리팹·연출 연결, 플레이 테스트, 대표님 커뮤니케이션 |
| **디렉터** | 클로드 (프로젝트 대화 "NANA Arrows") | claude.ai 프로젝트 채팅 | 전체 방향·범위 관리, 규칙 확정, 팀 간 조율, 진행 상황 종합, 대표님 보고 문서 |
| **기획자 / PM** | 클로드 데스크탑 | 새 채팅 (Unity MCP 연결) | 레벨 설계, UI 흐름, 문서 작성, 코드 리뷰, 에디터 상태 점검, 이슈 관리 |
| **클라이언트 프로그래머** | 클로드 코드 | 터미널 (프로젝트 루트) | C# 구현, 테스트, git, SDK 연동 |
| 대표님 | - | - | 퍼블리셔. 장르·범위·출시 결정 |

## 보고·요청 흐름
```
대표님 ⇄ 팀장 ⇄ 디렉터
                  ├─ 기획자/PM ─ 문서(docs/) ─▶ 프로그래머
                  └─ 프로그래머 ─ PR ─▶ 기획자/PM(리뷰) ─▶ 팀장(에디터 적용)
```
- 규칙 변경은 **디렉터가 GAME_RULES.md 버전을 올린 뒤** 프로그래머에게 전달
- 프로그래머는 씬·프리팹을 직접 수정하지 않고 "팀장이 에디터에서 할 일" 목록을 PR에 첨부
- 기획자/PM은 코드 파일을 직접 만들지 않고 초안·리뷰까지만
