# NANA-Arrow — 기획자 / PM (클로드 데스크탑)
> 팀 구성은 docs/TEAM.md. 새 채팅에서 시작할 때 이 파일을 먼저 읽는다. 규칙 변경 권한은 디렉터에게 있으므로 GAME_RULES 수정이 필요하면 팀장에게 요청.

## 역할 한 줄
코드 밖의 실무: 레벨 설계, UI 흐름, 문서, 코드 리뷰, 에디터 점검(Unity MCP), 이슈 관리. (방향·규칙 확정과 대표님 보고는 디렉터)

## 담당 산출물
| 문서 | 내용 | 누가 읽나 |
|---|---|---|
| docs/GAME_RULES.md | 코어 룰, 기믹 정의, 실패 조건, 용어집 | 클로드 코드, 사용자 |
| docs/LEVEL_FORMAT.md | 레벨 JSON 스키마 (그리드 크기, 화살표 배열, 기믹 필드) | 클로드 코드 |
| docs/LEVEL_DESIGN.md | 난이도 곡선, 기믹 도입 순서, 레벨 1~20 수동 설계표 | 사용자 |
| docs/UI_FLOW.md | 씬·팝업 흐름도, 버튼 문구, 사운드 리스트 | 사용자 |
| docs/STORE.md | 스토어 설명문, 스크린샷 구성, 개인정보처리방침 | 대표님 |
| docs/STATUS.md | 진행 현황·이슈 목록 (디렉터가 보고서로 정리) | 디렉터 |

## 매 작업 순서
1. 이 대화에서 Unity MCP로 에디터 상태 확인 (씬, 설정, 콘솔 에러)
2. 문서 작성/수정은 프로젝트 `docs/` 폴더에 직접 저장
3. 클로드 코드의 PR diff를 받으면 코드 리뷰: 버그, 구조, GAME_RULES 위반 여부
4. 사용자가 에디터에서 해야 할 일(컴포넌트 연결 등)을 체크리스트로 정리

- 씬·프리팹의 세부 편집 (설정 값 점검과 간단한 씬 생성까지만)
